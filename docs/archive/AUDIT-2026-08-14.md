## 🔴 严重 (S) — 8 项

| # | 位置 | 问题 |
|---|------|------|
| **S1** | `MainWindow.cpp:676-697,184-189` | **关窗时 worker 15s 超时未 join → 退出崩溃**。`stopWorkers` 的 `wait(15000)` 超时后仍继续，随后 MainWindow 析构销毁仍运行的 QThread 及其持有的 `decoder_/pipeline_/catalog_`（`~QThread` abort + worker 解引用已释放对象）。触发场景：退出时正做 >15s 操作——`mergeHdr` 无中途取消检查、大 RAW 解码、大文件导入拷贝。 |
| **S2** | `ImportWorker.cpp:69,170` + `CatalogDatabase.cpp:916-924` | **导入事务 begin/commit/rollback 返回值未检查**。COMMIT 失败（磁盘满/占用）时 `inTransaction_` 保持 `true` 导致事务悬挂，后续所有写入落入未提交事务、`optimize()` 恒报错；同时 `finishedImport` 照常发射——UI 显示"导入完成 N 张"，实际零记录。 |
| **S3** | `ImportWorker.cpp:69-77` + `CatalogDatabase.cpp:906-934` | **导入事务与并发 UI 写入共享同一连接**。导入事务只是翻转标志，UI 线程的 `saveAdjustments`/评分写入被吸收进同一事务；用户导入中改编辑 → 取消导入 → `rollbackTransaction()` 把已保存的编辑一并回滚。 |
| **S4** | `Parallel.cpp:91-96,130` | **parallelFor 调用线程参与循环无异常守卫 → UAF/terminate**。`fn` 在调用线程 chunk 抛异常（如 `ColorManager.cpp:177` `tlsScratch.resize()`、`Pipeline.cpp:381` `sumsBuf` 的 `bad_alloc`）→ 提前返回，已入队任务仍引用栈帧；池线程 `task()` 无 try/catch → `std::terminate`。 |
| **S5** | `Pipeline.cpp:1168-1178` | **任意 HSL 通道启用时，全局饱和度滑块被静默丢弃**。`useHsl` 分支走 `applyHSLPerChannel`，内部 satScale 不含全局 `a.saturation`。UI 同时暴露两个滑块，基础 Saturation=+50 + HSL 任意通道有值 → 饱和度提升失效。 |
| **S6** | `Pipeline.cpp:1262,1298-1300` | **锐化 masking 阈值错位形成死区**。Sobel 边缘图在 `sharpnessMasking>0.5` 才计算，`edgeScale` 在 `>0.1` 就读取 → masking∈(0.1,0.5] 时 edges 全 0、`edgeScale=0`，锐化被完全抑制（而 masking=0 反而全图锐化）。XMP 预设 `SharpenMasking=0.5` 即触发。 |
| **S7** | `DngConverter.cpp:26-33` | **rawBitDepth 移位 UB**。`(1u << bits)` 在 `bits==32` 时是 32 位无符号移位 ≥ 位宽（UB）。损坏 DNG `maximum≥2^31` 且 `raw_bps=0` 即触发，MSVC 下可能死循环。 |
| **S8** | `HdrMerge.cpp:103-104` | **merge() 空指针检查前解引用 `frames[0]`**。首帧为 null 即崩溃（其余帧均有 null 防御）。 |

## 🟡 轻微 (L) — 精选

- **截断 vs 舍入**：`RawDecoder.cpp:39`、`ColorManager.cpp:189`、`ExportEngine.cpp:53` 的 uint16/uint8 量化均无 `+0.5`，与 `toU16/toU8` 舍入不一致（≤1 LSB 偏暗）。
- **`>1` 输入行为不一致**：`Pipeline.cpp:1053-1060` 中性快速路径不 clamp，逐像素路径 clamp 到 [0,1]；HDR 输出一旦有任何调整高光即被截断。
- **JSON**：`Json.cpp:115-160` 解析无深度限制（深嵌套 .lrp 可栈溢出）；`parseNumber` 不查 inf/nan，序列化写出非法 JSON。
- **XMP**：`Xmp.cpp:50` 只按字面 `"crs:"` 前缀匹配，重写时未知 crs 字段（如 MaskGroupBasedCorrections）被丢弃。
- **SQLite 健全性**：无 `busy_timeout`；无 `user_version` schema 迁移号，靠列名启发式；`close()`/`backup_step` 返回值未检查。
- **缓存/开销**：`autoAdjust` 对 F32 整幅深拷贝（`Pipeline.cpp:1420`）；LRU `remove()` O(n)（`Pipeline.cpp:1762`）；`ensure()` 每次 `weakly_canonical`（`ThumbnailCache.cpp:89`）。
- **代次守卫**：`PreviewWorker.cpp` 串行执行下 `generation==latestGeneration_` 恒真，注释误导；`onFullResReady` 无代次比对会短暂显示陈旧帧。
- **UI 细节**：蒙版单击产生退化 undo 条目（`ImageViewport.cpp:381`）；导入取消不发 `finishedImport`（状态栏卡"导入 N/M"）；closeEvent 后 folderTimer 仍可能触发一次。
- **数据层**：`edit_history` 无限增长；启动不校验 `images.file_path` 存在；FNV 哈希无碰撞检测。
- **构建**：根目录/`harness/` 大量孤立 .obj/exe/pdb 残留且 `.gitignore` 未覆盖；`harness/build.bat` 硬编码 `C:\lrcproj2`；`dist/` 残留旧品牌 2.3.0 安装包；`vcpkg.json` 版本 1.0.0 与 2.11.0 不一致且含死依赖 opencv4；`LRC_USE_OPENCV` 为死选项。
- **文档**：声称 218 用例 vs 实际 245 个 `TEST_CASE`。
