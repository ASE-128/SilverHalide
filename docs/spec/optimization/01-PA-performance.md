# P-A 性能极致支柱 · 细化规格

> Status: DRAFT
> Last updated: 2026-09-22
>
> 本文档是优化方向 **P-A 性能极致** 的支柱细化规格，是
> [optimization-positioning-spec.md](../optimization-positioning-spec.md)（master）在
> P-A 维度的落地展开。**锚点数字、机器约定、In/Out of scope 一律以 master 为准**，
> 本文不新增任何量化承诺，只做子阶段拆解、代码域映射与可复现的验收方法。

## 1. 支柱目标

**P-A 性能极致** = **大图零等待 + 常驻轻量 + 主线程帧预算**，是差异化主战场。

- **大图零等待**：50MP 级 RAW 在 1:1 放大与编辑精帧下做到"感知零等待"（热路径毫秒级返回）。
- **常驻轻量**：内存峰值受控、切图后快速回落常驻基线，长会话、大目录不因累积占用而卡顿。
- **主线程帧预算**：连续编辑全程主线程不超帧预算，UI 无卡顿手感。

这一支柱直接承载 master 定位主张里的"重图编辑既不卡、也不吃爆内存"，与 P-B（离线 AI）、
P-D（稳定与工程债）互为支撑：P-A 提供手感与资源能力，P-D 保证其稳定可回归。

锚点数字**必须与 master 一字不差**，见第 2 节；master 定义的机器与样本约定同样适用：

- RAW 大图 ≥ **8000×6000（~50MP）**。
- 基准机器 = **目标发布配置（x64，独立 GPU 可选）** —— 即"独立 GPU 存在"不作为验收前提，
  无 GPU 机器也应达标；真机（含 GPU 机器）用于最终验收窗口，受沙箱 GPU 限制的机器不作为唯一裁决来源。

## 2. 量化锚点表（原样摘自 master）

| ID | 接受标准（可二值验证） | 归属主题 |
|----|----------------------|---------|
| B-1 | 50MP、默认调整、缓存命中：进入 1:1 出图 ≤ **175ms**；冷态（首次需解码）≤ 1500ms。 | 1:1 出图热/冷路径 |
| B-2 | 滑块拖动松手/停顿 → 1920 精帧 ≤ **80ms**。 | 编辑精帧 |
| B-3 | 50MP 连续编辑全程主线程问询 ≤ 16ms/帧（无 UI 卡顿）。 | 主线程帧预算 |
| D-1 | 编辑单张 50MP RAW 峰值内存 ≤ **1.2 GB**。 | 峰值内存 |
| D-2 | 切图后内存回落到常驻基线 ≤ **400 MB**。 | 常驻回落 |
| D-3（optional） | 打开 1 万张目录，胶片栏滚动 / 缩略图加载不掉帧。 | 大目录手感 |

方向级验收（来自 master AC-1）：B-1/B-2/B-3/D-1/D-2 在真机有实测记录，**≥4/5 达成**即视为
P-A 里程碑成立；不达标项须给出差距与后续计划。D-3 为 optional，不进入 4/5 计数。

> 注：B-1 的"冷态 ≤1500ms / 热态 ≤175ms"依赖解码与渲染路径是否命中缓存；按 currentContext
> 现有架构，热态命中指目录内嵌预览 / 磁盘 1:1 缓存 / 内存 LRU 任一命中即可直读免重复解码。

## 3. In scope / Out of scope（P-A 专属）

### In scope

- B-1/B-2/B-3/D-1/D-2 五条量化锚点的落地与真机（含 GPU 机器）量化验收（须有实测记录）。
- D-3（optional）大目录手感作为 stretch，允许在里程碑验收之前标为 optional 不强制。
- 支撑上述锚点所需的：解码 / 渲染热路径、缓存（LRU / 磁盘 / 内嵌预览）命中率、内存生命周期、
  主线程帧预算审计、SIMD / GPU（可选）后端加速。
- 将验收结果回写 master AC-1 的实测记录。

### Out of scope（P-A 专属）

- 性能之外的功能开发（归属 P-B/P-D 或常规功能迭代）。
- 任何新的 Lightroom 兼容投入 / 互导验收（master 已整体移除，P-A 不例外）。
- P-A 之外的稳定性工程债（flaky / 并发 / 崩溃）归属 P-D，本文不展开。
- macOS / Linux 移植、插件 / SDK、生成式 AI、超分（P-B optional），不属于 P-A。
- 不承诺 100MP / 长焦拼接图同样达标（master Edge cases 明确未承诺）。

## 4. 子阶段拆分（可逐步验收）

按"先手感、再内存、后规模"递进，每个子阶段可独立答辩，避免一次性验收五条锚点造成黑箱。

| 子阶段 | 覆盖锚点 | 范围说明 | 验收方法 |
|--------|---------|---------|---------|
| **1a 1:1 热路径** | B-1 | 进入 / 退出 1:1 放大、缓存（目录内嵌预览 / 磁盘 1:1 / LRU）直读路径、热/冷态分支、全尺寸缓冲生命周期（至多 1 份、退出即释放）。 | 对固定 50MP 样本分别测热态与冷态进入 1:1 的 wall-time；热态 ≤175ms、冷态 ≤1500ms；记录冷态未命中归因。 |
| **1b 编辑手感（精帧）** | B-2、B-3 | 滑块 coarse-then-refine 的 1920 精帧触发时机（松手/停顿 ≥80ms，即 dict 节流的停顿口径）、精帧渲染耗时、主线程帧预算审计。 | 脚本化拖动滑块 → 松手计时到 1920 精帧；重复 N 次取稳态；主线程用 profiler 记录每帧问询占用，验证 ≤16ms/帧。 |
| **2 内存极致** | D-1、D-2 | 峰值内存控制（编辑 50MP 单张全流程）、切图后的内存回落策略（释放全尺寸缓冲、清缓存所有者、GC）。 | 用进程私有内存峰值采样记录编辑全流程峰值；切图后定时采样回落曲线，验证 ≤400MB 并稳定。 |
| **3 大目录** | D-3（optional） | 1 万张目录下胶片栏滚动 / 缩略图请求节流与复用，验证不掉帧。 | 构造 1 万条目录，滚动胶片栏并测渲染帧间隔；任其失败也不影响里程碑 4/5 计数。 |

子阶段依赖关系：1a → 1b（共用解码/缓存底座）；2 可与 1 并行推进但验收校准依赖 1a 的缓冲生命周期；
3 独立，可与 1 并行。

## 5. 代码域映射（候选落点，非断言改动）

以 currentContext 分层为依据，标注锚点可落到 engine / catalog / ui 的**候选落点**。
**本表只标"可能涉及的资金码域"**，不做具体改动断言，具体实施由后续实施规格裁定。

- **engine /（线性缓冲与管线）**
  - 全线性 ProPhoto 缓冲 `ImageBuffer`（全尺寸 ~360MB 级）、`resize` 面积平均、`Pipeline.render`
    coarse-then-refine 语义、`renderLinearFull` + `toDisplaySRGB`。→ **B-1 / B-2 / D-1** 的主要算力域。
  - `PipelineCacheKey(imageId, adjustments.hash(), maxDim)` 的 LRU 命中粒度与 256MB 容量策略 → **B-1 / B-2 热态**、**D-2 回落**配套。
  - SIMD / 可选 GPU 后端（如 `LRC_ENABLE_SIMD` 的 AVX2 路径思路）→ 精帧 / 1:1 耗时改善池。

- **catalog /（目录与磁盘缓存）**
  - `previews` 内嵌预览（320px 缩略图 + 1:1 JPEG，导入预生成）、磁盘 thumbnails 缓存与原子写、1:1 磁盘直读。→ **B-1 热态、冷态/探测**、**D-3 缩略图加载**。
  - 1 万张目录下胶片栏的缩略图请求来源与复用。→ **D-3**。

- **ui /（PreviewWorker 与主线程预算）**
  - `PreviewWorker`（QThread）串行处理预览请求、`fullResReady` 信号、coarse/refine 触发、generation 丢弃过时结果、`batchExport`。→ **B-1 / B-2 触发与调度**、**B-3 主线程免卡顿**。
  - 主线程职责（布局/事件/直方图/DB 读）与 16ms/帧预算审计点。→ **B-3**。

> 归属原则提醒：engine/catalog 必须保持 Qt-free（可在 headless 构建下 CT Deployed 测试）；
> 新增性能能力若落入这两层，应补 Catch2 单测而非只做 UI 表现验证。

## 6. 量化验收方法

统一测量口径，保证同一锚点由不同人复测可得一致结论。

### 6.1 通用约定

- **样本**：固定的 50MP（≥8000×6000 ~50MP）RAW 大图；B-2/B-3 使用"默认调整 + 一组代表性主滑块
  （曝光/对比度/高光/阴影/白/黑/色温）"作为脚本驱动参数。D-3 使用 1 万条构造目录。
- **时机**：
  - B-1 热态：连续两次进入 1:1，取**第二次**（缓存命中）计时；冷态：清空缓存后**首次**进入计时。
  - B-2：最后一个滑块"停顿/松手"到精帧信号的 wall-time。
  - B-3：连续编辑 ≥10 次调整操作，全程采样主线程每帧问询占用，取最大值/均值。
  - D-1：编辑单张全流程（进 1:1 + 拖若干滑块）峰值即 `WorkingSet` / 私有内存峰值。
  - D-2：从 D-1 峰值切到另一张图后，定时（如 0.5s/1s/2s/5s）采样回落曲线，验证到 ≤400MB 并保持。
- **对比基线**：以 master AC-1 为目标线；同一机器上先测"改动前"基线再测"改动后"，差值用于归因。
  若改动了缓存/缓冲生命周期，需同时给出 hot/cold 两组数字以区分命中率与算力。
- **工具**：耗时用高精度时钟 / 各自 profiler（本机）、内存用进程私有内存采样（任务管理器或采样 API 均可，
  注明口径即可）；数据落在可见的验收记录，供回写 master。
- **真机窗口**：最终验收在**真机（含独立 GPU 可用机器）** 执行；沙箱 GPU 受限机器不作为唯一裁决。
  D-1/D-2 内存口径对真机与本机一致。

### 6.2 通过判定

- 五条锚点 B-1/B-2/B-3/D-1/D-2 真机实测，**≥4/5 达成** → P-A 里程碑成立；
  不达标项记录差距与后续计划（遵循 master AC-1）。
- D-3 达标与否均属 optional，不进入 4/5 计数。

## 7. 风险与注意

- 50MP 之上（100MP/拼接）不承诺达标（master Edge cases）。
- B-1 冷态 <1.5s 依赖磁盘 1:1 缓存命中；缓存被清/目录为空时不可作为冷态达标判据的合理样本。
- D-2 回落的成功不仅看数值，还需确认"从峰值回落到 ≤400MB"是可重复的，防止临时命中快照造成假阴性/假阳性。
