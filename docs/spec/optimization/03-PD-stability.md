## 1. 支柱目标

P-D（稳定与工程债）的目标是**让 P-A（性能极致）与 P-B（离线 AI）的成果长期可维护、可依赖**。
它围绕四个具体方向收敛工程债：**flaky 测试、内存泄漏、目录并发、崩溃率（SIGSEGV / 无响应 / use-after-free）**。

核心判定准则一句话：

> **回归全绿是硬门槛，任何零散的 flaky 都不应被当作"已知取舍"带进发布。**

- 稳定是 P-A 性能锚点（B-1..D-3）和 P-B 离线 AI 得以成立的**基础层**：性能/ AI 结果若在运行时随机
  崩溃、内存越啃越多、或目录并发下数据漂移，量化锚点与 AI 能力都无法被信任。
- 本支柱**不产生新功能**，只负责把已有功能做成"可复现、可回归、不闹鬼"。

### 1.1 为什么排在 P-A / P-B 之后

按 master 定位文档，支柱优先级 **A > B > D**，P-D 是 **支撑性**支柱（排在 P-A / P-B 之后）。
但它同时是它们**前置使能项**：P-A/P-B 的验收（实测锚点、headless `[ai]` 单测绿）都需要先有稳定的
CI/回归基线。因此本文档的工作节奏为：**在 P-A/P-B 每轮改动落地后同步收口稳定项，而不是独立大拆大改。**

## 2. 优先级与节奏

| 维度 | 结论 |
|------|------|
| 支柱权重 | 支撑性（P-D < P-A、P-B） |
| 与 P-A/P-B 的关系 | 前置使能项：回归全绿是先决条件 |
| 工作节奏 | 跟随 P-A/P-B 每轮集成交互进行，不单独开大线 |
| 硬门槛 | 全量 headless 全绿 + GUI 冒烟 `SMOKE_EXIT=0` |

## 4. 稳定项分类与优先级（设计）

P-D 的稳定项按风险等级分四类。优先级 S1 > S2 > S3 > S4，工作顺序严格沿此序推进。

| 类别 | 主题 | 判定信号（触发条件） | 优先级 | 典型动作 |
|------|------|---------------------|--------|---------|
| **S1** | 崩溃 / 内存泄漏 | SIGSEGV、访问非法内存、use-after-free、长跑内存单调上涨、异常路径未释放 | 最高，阻断性 | SEH/断言补齐、RAII 审计、长跑泄漏基准、崩溃现场复现 |
| **S2** | 并发 / 竞态 | 多线程 worker 退出竞态、事件线程异常回退、目录/预览 worker 共享状态并发访问 | 高 | 线程生命周期固化、竞态回归测试、`atomic`/`busy_timeout` 审计 |
| **S3** | flaky 测试 / 阈值 | 同一用例运行间非确定通过/失败、断言阈值过近、依赖 DLL 搜索顺序 | 中（回归可信度） | 阈值加余量、稳定化、环境隔离（DLL 部署与搜索顺序） |
| **S4** | 目录并发 / 大库 | 超万张目录、导入/预览并发写库、智能收藏夹全表刷新、UI 线程长任务 | 低（随规模增长） | 后台化、批量化、并发写队列压力测试 |

### 4.1 各类填写口径

- **S1（优先）**：以"崩溃率与泄漏"为第一目标。任何崩溃（断言、SIGSEGV）都先于性能/AI 落地。
  泄漏以"长跑内存曲线单调上涨"为判据，不追求指针级全覆盖审计，优先覆盖热点路径。
- **S2**：固定"worker 线程 abort+quit 生命周期契约"，让"关窗/切图/取消"在任何时序下都安全。
- **S3**：目标是**消灭非确定性**——同一测试 N 次运行结果一致；ND 阈值类断言给足余量或用确定性参考。
- **S4**：目录并发与超大库是 P-A D-3（打开 1 万张目录不掉帧）的前置条件，随规模压力推进。

## 5. 回归要求（硬门槛）

P-D 的验收以 CI/回归为单一入口，任何改动合入前必须满足：

- **全量 headless 全绿**：`cmake -S . -B build_headless -DCMAKE_BUILD_TYPE=Release -DLRC_ENABLE_QT=OFF`
  → `cmake --build build_headless -j` → `ctest --test-dir build_headless --output-on-failure`。
- **GUI 冒烟 `SMOKE_EXIT=0`**：`build_gui/tests/lrc_tests.exe`（GUI 用例）与 `SMOKE_EXIT=0`
  启动冒烟退出码必须为 0，不得出现假卡死/退出崩溃。
- **连续零随机失败**：被判定为稳定的用例，连续 N 次（建议 ≥3）运行零随机失败后方可从"待稳定"转绿。
- **新增回归测试登记**：修复稳定项时，对应回归测试登记到 [tests/CMakeLists.txt](../../../tests/CMakeLists.txt)，
  并纳入 headless 全量回归。

### 5.1 环境性问题的处理约定

对 S-r-01 这类环境性问题（Debug 缺 ORT DLL 加载了系统旧版），须通过**构建/部署隔离**解决，
而不是改测试断言绕过；Release 与 Debug 输出目录在验收时都应部署正确的 ORT 1.23.0 DLL。

## 6. In scope / Out of scope（P-D 专属）

### In scope

- S1 崩溃与内存泄漏的定位与修复（阻断 P-A/P-B 的那部分）。
- S2 worker 线程生命周期契约与竞态回归（含 S-r-03/S-r-04 的防回退）。
- S3 flaky 测试稳定化与阈值余量处理（含 S-r-02 R-08 ICC 阈值）。
- S4 目录并发/大库支撑（为 P-A D-3 铺路）。
- 全量 headless 全绿 + GUI 冒烟零失败的回归门槛建设。
- 稳定项每次修复的回归测试登记到 `tests/CMakeLists.txt`。

### Out of scope（P-D 专属）

- 新增任何产品功能（功能由 P-A/P-B/竞品对齐波承担）。
- 指针级全量内存审计（只覆盖热点/崩溃路径）。
- 跨平台移植、插件 SDK、LR 兼容（沿用 master Out of scope 护栏）。
- 已知取舍项的能力补齐（如 S-r-05/S-r-06 的 TIFF 压缩读取、全尺寸预览）不归 P-D。

## 7. 验收标准（每类可验证）

> 每类验收以**可二进制判断**的标准为准，写进文档并在该稳定项落地后勾选。

| 类别 | 验收标准（可验证） | 判定 |
|------|-------------------|------|
| S1 | 记录崩溃/泄漏热点并修复；修复项无新增回归失败；热点路径长跑内存曲线不再单调上涨 | 通过/未达 |
| S1 | 任意 SIGSEGV/断言在 headless 全量中重现次数降为 0 | 通过/未达 |
| S2 | worker abort+quit 生命周期契约以并发/切图/取消时序回归测试锁定；连续 N 次无竞态失败 | 通过/未达 |
| S3 | flaky 用例（如 R-08 ICC 断言）改为确定性/有余量后，连续 N 次零随机失败 | 通过/未达 |
| S4 | 打开 ≥1 万张目录并发导入/预览场景无明显 werror、无数据漂移；大库刷新不阻塞 UI 线程 | 通过/未达 |
| 全局（硬门槛） | 全量 headless 全绿 + GUI 冒烟 `SMOKE_EXIT=0`；新增回归测试已登记 `tests/CMakeLists.txt` | 通过/未达 |

> 约定：N（连续绿运行次数）取 ≥3；每次稳定项修复登记具体的回归测试用例到 `tests/CMakeLists.txt`，
> 避免把修复项带出回归覆盖范围。
